# Shared conversation client

`@agentui/client` provides a conversation store for desktop and iOS consumers. Its core compiles against ES2023 without browser or Node globals. `@agentui/client/react` exports `useConversation(store)` using React's external-store subscription API. The package contains no transport, authentication, native adapter, or platform storage implementation.

Create a store with `createConversationStore({ scope, port, projection, drafts, createCommandId })`. The scope contains both host and conversation IDs. The port must belong to that scope. The command ID generator must return a fresh nonempty ID accepted by the shared contracts.

Each store needs its own `DraftStoragePort` instance. `load(scope)` returns `null` or the saved records and claims the conversation for that port. A later loader supersedes earlier ports, whose saves must reject without writing. `save(records, imageChange?)` resolves only after the record and optional image byte changes commit together. `loadImage(scope, selectionId)` reads the separately stored bytes. Desktop shares one canonical store among the active view, captured sends, and recovery workers.

LocalRecords version 3 requires both `image` and `frontendSends`. Exact released version 1 text records and version 2 image records restore without writes. The next mutation saves version 3. Private frontend-only version 2, mixed formats, unknown fields, and malformed journals are refused without changing records or bytes.

Await `store.ready` to load the draft and outbox. Hydration failure sets the failed connection view and still rejects `ready`; the store observes that rejection internally so an unawaited `ready` does not become an unhandled promise. Call `connect()` to request a fresh host snapshot. The immutable view exposes `document`, `cursor`, `draft`, `outbox`, and `connection`. Subscribers run synchronously and must not throw. A subscriber exception propagates to the operation that publishes the view. Subscribe directly or call `useConversation(store)` from a React component. `disconnect()` closes the current feed and invalidates late callbacks. `connect()` always starts from a snapshot, including after a sequence gap.

`setDraft(text)` persists an edit. `send()`, `approve(pendingId, choiceId)`, and `cancel(runId)` persist the exact command before submission. A failed save prevents submission. A rejection on the initial submission durably removes the outbox entry and preserves the draft. A failed removal save retains the original entry. A lost reply or pending/uncertain receipt leaves the command in the outbox. A refusal on retry also retains the entry because it cannot disprove an earlier admission; reconcile the original identity through the host outcome. `retry(clientCommandId)` explicitly resubmits that exact persisted command with the same ID. The store never retries a side effect automatically.

`selectImage(file)` saves the selection and bytes before uploading. `retryImage()` reuses the original upload identity and bytes. `removeImage()` removes metadata and bytes together. Composer `send()` includes the selected ready image, while explicit `send(text)` preserves that image and sends only text. Images cannot be combined with captured frontend tools. That composer send throws `FrontendImagesUnsupportedError` before admission and leaves the draft, image, and existing captures intact.

The optional `frontend` admission captures the offer and its original owner together for a send. The store durably saves that exact command in the outbox and `frontendSends` journal before committing the capture or submitting it. If the authority changes during the save, the store records `unavailable-pending` and refuses submission. Retrying preserves the original command and requires its retained capture. Journal references survive outbox settlement so recovery can notify the original owner without executing a handler or submitting again.

`dispose()` closes admission and the feed synchronously, then drains admitted local writes. Repeated calls return the same drain promise. Disposal does not wait for transport or upload replies, and late replies cannot write to the closed store. A successful drain does not mean prior operations succeeded. A failed load still rejects `ready`, preserves the failed connection state, and rejects operations without rewriting corrupt records. Failed writes still reject their operations. Applications can close the physical storage lease after this local drain.

A snapshot changes only the host document and cursor. It preserves the local draft and outbox, even if the host document now reports a completed command whose response was lost. Use `document.receipts[entry.command.clientCommandId]` to display the known host outcome beside a local outbox entry. Its presence does not mean a new command should be generated. An explicit retry can obtain the existing receipt and settle the saved local entry. Accepted or completed replies clear a sent draft only when its captured revision still matches. A newer draft with identical text is preserved.

`projection.apply(state, event)` must return the next state without mutating either input. The store freezes published domain state.

Feed pages apply atomically. The store retains at most 256 sequence identities to recognize exact duplicates. A changed duplicate, older duplicate with no retained identity, or gap requests explicit resynchronization. Scope and projection version mismatches stop the connection. These failures never fabricate an applied cursor.

`checkCompatibility(client, host)` reports independent wire, extension SDK contract, native runtime, deployment revision, and applied artifact mismatches with corrective actions. Its inputs are trusted typed values. The caller must validate decoded compatibility exchange data before calling it; the frozen conversation port does not provide that exchange. An application version alone cannot establish compatibility. Native compatibility is an exact engine, version, and session-format tuple. A desired Git revision and the identity of the artifact actually applied remain separate facts.

The tests exercise emitted exports, the store with injected ports, React updates in Chromium, and ambient-type isolation. These checks do not establish Apple or React Native execution or live-provider behavior.
